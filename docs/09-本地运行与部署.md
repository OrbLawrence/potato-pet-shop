## 3. 初始化数据库

1. 创建数据库与独立账号：

```sql
CREATE DATABASE pet_shop DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'petshop'@'%' IDENTIFIED BY 'replace-with-strong-password';
GRANT ALL PRIVILEGES ON pet_shop.* TO 'petshop'@'%';
FLUSH PRIVILEGES;
```

2. 导入本仓库的 DDL：

```bash
mysql -u petshop -p pet_shop < code/database/schema.sql
```

3. 按需插入你自己的演示数据（本仓库不提供种子数据）。

> 生产环境不要使用 `root` 账号，也不要把密码写进 SQL 文件。

## 4. 启动基础设施

### 4.1 Redis

```bash
docker run -d --name petshop-redis -p 6380:6379 redis:7
```

### 4.2 Nacos

```bash
docker run -d --name petshop-nacos -p 8848:8848 -p 9848:9848 \
  -e MODE=standalone nacos/nacos-server:v2.2.3
```

启动后访问 `http://127.0.0.1:8848/nacos`，确认服务正常。

### 4.3 Dify

按 Dify 官方文档部署，创建：

1. 知识库，导入 `code/agent/knowledge/` 中的文档（或你自己的完整知识库）。
2. Chatflow 应用，按 `code/agent/dify/chatflow_config.yml` 配置节点。
3. 发布应用，生成 API Key。
4. 把 API Base 与 Key 写入环境变量。

## 5. 启动后端

```bash
cd pet-shop-cloud
mvn -B -DskipTests package
```

依次启动：

1. `PetGatewayApplication`（8080）
2. `PetUserServiceApplication`（9001）
3. `PetBizServiceApplication`（9002）
4. `PetProductServiceApplication`（9003）
5. `PetAiServiceApplication`（9004）

验证：

```bash
curl http://localhost:8080/actuator/health
```

Nacos 控制台应能看到 5 个服务实例。

## 6. 配置 Nginx

参考配置（只保留关键部分）：

```nginx
server {
    listen 3000;
    server_name localhost;

    root /path/to/pet-shop-frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location /api/ai/ {
        proxy_pass http://127.0.0.1:8080/ai/;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 180s;
        proxy_set_header Connection '';
        proxy_http_version 1.1;
    }
}
```

要点：

- `try_files` 支持 Vue history 路由。
- `/api/ai/` 必须关闭代理缓冲，否则 SSE 会被 Nginx 聚合。
- `proxy_read_timeout` 要大于 AI 服务超时。

## 7. 构建 Web 端

```bash
cd pet-shop-frontend
npm install
npm run build
```

把 `dist/` 放到 Nginx 的 `root` 目录，重启或 reload Nginx。

开发模式：

```bash
npm run dev
```

## 8. 构建小程序

`.env.production` 示例：

```dotenv
VITE_API_BASE_URL=https://your-domain.com/api
```

本地真机调试示例：

```dotenv
VITE_API_BASE_URL=http://192.168.1.100:3000/api
```

构建：

```bash
cd pet-shop-miniapp
npm install
npm run build:mp-weixin
```

在微信开发者工具中导入：

```text
pet-shop-miniapp/dist/build/mp-weixin
```

注意事项：

- 手机与电脑在同一局域网。
- 本地使用 HTTP 时，在开发者工具中勾选“不校验合法域名”。
- 正式发布必须使用 HTTPS，并在微信公众平台配置 request 合法域名。
- 修改 `.env.production` 后必须重新构建。

## 9. 启动顺序建议

```text
MySQL -> Redis -> Nacos -> Dify
  -> user-service / biz-service / product-service / ai-service
  -> gateway
  -> Nginx
  -> Web / 小程序
```

先启动业务服务，再启动网关，避免网关启动时找不到实例。

## 10. 常见问题

| 现象 | 排查 |
| --- | --- |
| 网关 503 | 服务未注册到 Nacos；检查 `NACOS_ADDR` 与服务日志 |
| 登录 401 | token 过期、JWT Secret 不一致、网关未放行路径 |
| 商品列表不更新 | Redis 缓存未清理；检查商品增删改后的 `evictListCache` |
| 下单提示库存不足 | 库存被其他订单占用；刷新后重试 |
| 余额支付失败 | 余额不足或并发扣减；检查条件 UPDATE 影响行数 |
| AI 无响应 | Dify 未启动、Key 错误、超时太短、Nginx 缓冲未关闭 |
| 小程序请求失败 | Base URL 不是局域网 IP、防火墙未放行 3000、未重新构建 |
| 图片上传失败 | OSS Key/Endpoint/Bucket 配置错误、权限不足 |

## 11. 生产部署提示

- 使用 HTTPS 与正式域名。
- 数据库、Redis、Nacos 不暴露公网。
- 网关限制 CORS 来源，不要使用 `*`。
- 所有密钥从环境变量或密钥管理服务注入。
- 为 AI 接口增加限流与配额。
- 为上传接口增加类型/大小校验与病毒扫描。
- 配置日志轮转与监控告警。
- 定期备份数据库，并验证恢复流程。
