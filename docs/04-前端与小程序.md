### 2.1 路由与角色

路由分为三组：

- `/`：品牌落地页，公开访问。
- `/admin/**`：管理端，要求 `role = admin`。
- `/user/**`：用户端，要求 `role = user`。

```js
router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  const role = localStorage.getItem('role')
  const isLoggedIn = !!token

  if (to.meta.requiresAuth && !isLoggedIn) {
    next('/login')
    return
  }

  if (to.meta.role && to.meta.role !== role) {
    next(role === 'user' ? '/user/home' : '/admin/dashboard')
    return
  }

  next()
})
```

### 2.2 Axios 拦截器

请求拦截：

- 从 `localStorage` 读取 token。
- 自动加上 `Authorization: Bearer <token>`。

响应拦截：

- `code = 200`：直接返回 `res`。
- `code = 401`：清除 token、提示、跳转登录页。
- 其它错误：统一弹出 `ElMessage`。

```js
if (res.code === 200) {
  return res
} else if (res.code === 401) {
  localStorage.removeItem('token')
  router.push('/login')
  return Promise.reject(new Error('登录已过期'))
}
```

### 2.3 API 分层

`api/index.js` 按领域封装：

- `dashboardApi`

页面只调用语义化方法，不直接拼 URL，便于统一改路径与加参数。

### 2.4 布局

- `Layout.vue`：管理端左侧菜单 + 顶部用户信息 + 修改密码弹窗。
- `UserLayout.vue`：用户端顶部导航 + 余额展示 + 修改密码弹窗。

两个布局都从 `localStorage` 读取用户名，退出登录时清理本地状态并跳转登录页。

### 2.5 数据看板

`Dashboard.vue` 使用 ECharts 渲染两个环形图：

- 宠物种类分布。
- 宠物性别分布。

数据来自 `GET /dashboard/statistics`，后端返回 `categoryData` 与 `genderData` 两个数组，前端直接映射为 `name/value`。

### 3.1 请求封装

`utils/request.js` 做了四件事：

1. 拼接 `BASE_URL`。
2. 自动携带 `Authorization`。
3. 统一处理 `Result`：`code = 200` 时直接返回 `data`。
4. `401` 时清理本地登录态并跳转登录页。

```js
if (isUnauthorized) {
  clearAuth()
  uni.showToast({ title: '登录已过期，请重新登录', icon: 'none' })
  setTimeout(redirectToLogin, 600)
  reject(new Error('登录已过期'))
  return
}
```

### 3.2 商品购买页

`pages/shop/index.vue` 覆盖了完整的购买流程：

- 商品列表与库存标签。
- 加入购物车、加减数量。
- 选择门店。
- 选择支付方式（余额/模拟微信/模拟支付宝）。
- 提交订单并刷新余额。
- 订单列表与订单详情。

页面把“购物车状态、门店列表、支付渠道、订单提交”放在同一个页面内，减少小程序页面跳转带来的状态丢失。

### 3.3 AI 页

`pages/ai/index.vue` 的关键点：

- 消息列表自动滚动到底部。
- 生成中显示“正在思考”与光标。
- 支持停止生成。
- 支持开启新对话（清空会话 ID）。
- 流式失败时自动降级到阻塞接口。

## 4. SSE 流式问答

### 4.1 Web 端

Web 端使用 `fetch` + `ReadableStream`：

```js
const reader = response.body.getReader()
const decoder = new TextDecoder('utf-8')
let buffer = ''

while (true) {
  const { value, done } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  // 按行解析 data: {...}
}
```

事件协议：

| 事件 | 含义 |
| --- | --- |
| `message` | 一段回答内容，前端追加到气泡 |
| `conversation` | 会话 ID，前端保存用于下一轮 |
| `done` | 本轮结束，停止 loading |

### 4.2 小程序端

小程序使用 `uni.request` 的 `enableChunked: true` + `onChunkReceived`：

```js
const task = uni.request({
  url: `${BASE_URL}/ai/chat`,
  method: 'POST',
  enableChunked: true,
  onChunkReceived: (res) => {
    const text = decoder.decode(res.data, { stream: true })
    handleText(text)
  }
})
```

如果当前环境不支持分块接收，页面在 `onDone` 时发现没有收到任何内容，会自动调用 `/ai/chat/blocking` 重新获取完整答案。

### 4.3 为什么不用 WebSocket

- AI 回答是“一次请求、多次推送、最终结束”的单向流，SSE 更贴合。
- SSE 基于 HTTP，鉴权、网关转发、Nginx 配置都更简单。
- 小程序对 `enableChunked` 的支持足够覆盖演示场景，且保留了阻塞降级。

## 5. 跨端差异

| 差异点 | Web | 小程序 |
| --- | --- | --- |
| 请求库 | Axios | `uni.request` |
| 流式接收 | `fetch` + `ReadableStream` | `enableChunked` + `onChunkReceived` |
| 登录态 | `localStorage` | `uni.setStorageSync` |
| 路由 | Vue Router | `pages.json` |
| 提示 | Element Plus `ElMessage` | `uni.showToast` |
| 降级 | 无 | 阻塞接口 |
